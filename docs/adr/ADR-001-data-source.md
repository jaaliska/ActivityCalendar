## Контекст

Приложение показывает календарь спортивных активностей за произвольный месяц любого года.
Источник тренировок — часы Garmin. Требования к данным:

- **История за все годы** — это главная фича, ради которой проект и затевается
  (в Strava нельзя листать назад).
- **Тип активности** — обязателен и должен различаться на уровне иконки
  (главная претензия к календарю в Garmin Connect).
- **Дата, длительность, дистанция** — для сводок за месяц.
- **Автообновление** новых тренировок — желательно, но не критично для MVP.

Ограничения проекта: один разработчик, некоммерческий пет-проект, нет юрлица,
нет платной подписки Strava и покупать её не планируется.

## Рассмотренные варианты

### 1. Garmin Connect Developer Program (Activity API / Health API) — ❌ недоступен

Официальный cloud-to-cloud API, тот самый, через который Garmin пушит тренировки в Strava.

Не self-serve: доступ выдаётся по партнёрскому ревью. Подаваться нужно как юрлицо
с корпоративной почтой и коммерческим кейсом; личные проекты отсекаются на входе.
По состоянию на 2026 год приём новых заявок приостановлен, публичная форма запроса убрана,
дата возобновления не объявлена. У Health API для продакшн-тира также фигурирует
единовременный административный сбор порядка нескольких тысяч долларов.

**Вывод:** путь закрыт независимо от качества проекта.

### 2. Неофициальный веб-API Garmin Connect (`garth` / `python-garminconnect`) — ❌ сломан

Эндпоинты, которые использует мобильное приложение Garmin. Долго был народным решением
для личных скриптов.

В марте 2026 Garmin изменила флоу аутентификации. Библиотека `garth`, на которой держалась
почти вся экосистема, объявлена deprecated (финальный релиз 28.03.2026). Новые логины
не работают; доживают только ранее сохранённые сессии, до истечения OAuth1-токена.
Плюс это серая зона по ToS и порт логики на Kotlin с нуля.

**Вывод:** строить нельзя, фундамент уже развалился.

### 3. Connect IQ SDK (приложение на самих часах) — ❌ не решает задачу

Бесплатный открытый SDK, отдельная от Developer Program история. Но приложение на часах
видит текущую тренировку и дневные метрики, а не архив сохранённых активностей.
Сами часы хранят `.FIT`-файлы только за последнее время — это буфер, а не история.

**Вывод:** не тот уровень доступа.

### 4. Прямое чтение `.FIT` с часов по USB/BLE — ❌ несоразмерно

Технически возможно (протокол реверс-инжинирился в открытых проектах), но это
многомесячная работа с проприетарным протоколом и парсингом бинарного формата,
при этом на устройстве всё равно лежат не все годы.

**Вывод:** цена в разы выше ценности.

### 5. Strava API — ⏸ отложено

Работоспособный вариант, но с 1 июня 2026 доступ к Standard Tier требует активной платной
подписки Strava, которой нет и не планируется. Плюс это данные «из вторых рук»
и зависимость от платформы, которая меняла правила программы трижды за два года.

**Вывод:** возможен как третий источник в будущем, не сейчас.

### 6. Health Connect + разовый экспорт архива Garmin — ✅ выбрано

Health Connect — системное локальное хранилище health-данных Android, официальный Jetpack API.
Garmin Connect пишет в него тренировки (тип, длительность, дистанция), пульс, шаги, сон.
Чтение — `ExerciseSessionRecord` с фильтром по диапазону дат, инкрементальные обновления —
через ChangeLogs.

Ключевое ограничение: Health Connect не даёт ретроспективу. По умолчанию читаются данные
не глубже 30 дней до выдачи разрешения (снимается разрешением
`PERMISSION_READ_HEALTH_DATA_HISTORY`), но главное — Garmin пишет туда только с момента
включения интеграции и не заливает прошлые годы задним числом.

Поэтому решение гибридное: историю даёт разовый экспорт данных аккаунта Garmin
(архив со всеми активностями за всё время), а текущий поток — Health Connect.

## Решение

**Два источника данных, скрытые за интерфейсом `ActivitySource`:**

```
Разовый бэкфилл истории              Постоянный поток
─────────────────────────            ──────────────────────
Экспорт данных аккаунта Garmin  →    Часы → Garmin Connect → Health Connect
   (уточнено: CSV с сайта)
            ↓                                      ↓
            └───────────→  Room (локальная БД)  ←───┘
                                   ↓
                              Календарь
```

- Локальная БД — **единственный** источник для UI. Она не оптимизация, а ядро:
  только она даёт мгновенную прокрутку по годам, работу оффлайн и независимость
  от 30-дневного окна Health Connect.
- Дедупликация записей — по времени старта активности с допуском в несколько секунд.
  *Уточнено 2026-08-20: по **локальному** времени старта, допуск не нужен — значения
  во всех источниках совпадают точно.*
- Абстракция `ActivitySource` обязательна с первого дня: источников сразу два,
  а Strava может стать третьим.

## Последствия

**Положительные**

- Всё держится на официальных API, ничего не отвалится от смены партнёрских правил.
- Health Connect — актуальный Jetpack API с современной моделью разрешений; хороший
  учебный материал и вменяемая строчка в портфолио.
- Данные локальные, никакого бэкенда, аккаунтов и OAuth-сервера не нужно.

**Отрицательные / принимаемые риски**

- Пополнение истории за прошлое — ручная операция (заказать экспорт, скормить архив).
  Приемлемо: делается раз в год.
- Таксономия типов у Health Connect своя (`EXERCISE_TYPE_*`, ~80 значений) и не совпадает
  с типами Garmin один к одному. Часть активностей может схлопываться в общий тип —
  проверяется в спайке (Блок 0), при необходимости тип достаётся из названия тренировки.
- Фирменные метрики Garmin (Body Battery, Stress, Intensity Minutes, Training Load)
  через Health Connect не приходят. Для календаря активностей не нужны.
- При удалении приложения разрешения отзываются и 30-дневное окно отсчитывается заново —
  ещё одна причина хранить всё у себя и предусмотреть бэкап/экспорт своей БД.
- Требуется Health Connect на устройстве и включённая интеграция в Garmin Connect.
  Само приложение Health Connect работает только с Android 9 (API 28) и выше: на Android 9–13
  ставится отдельно из Play Store, с Android 14 — системный компонент ОС. SDK
  `connect-client` формально собирается и с API 26, но на 26–27 Health Connect недоступен
  физически. Поэтому `minSdk = 28`: минимум диктует приложение, а не SDK.

## Когда пересмотреть

- Garmin возобновит приём в Developer Program и начнёт пускать индивидуальных разработчиков.
- Появится платная подписка Strava или Strava откроет бесплатный тир → добавить
  третий `ActivitySource`.
- Health Connect перестанет получать от Garmin тип активности в пригодном виде.
