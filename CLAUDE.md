# ActivityCalendar

Календарь спортивных активностей с Garmin. Solo pet-project, учебный.
План работ: @docs/plan/milestone-dev-plan.md
Решение по источнику данных: @docs/adr/ADR-001-data-source.md
Поля источников и доменная модель: @docs/data-model-notes.md
Откуда берутся данные и когда их нет: @docs/data-sources.md

## Стек
Kotlin, Jetpack Compose, Room, Health Connect. Минимальный SDK 28 —
приложение Health Connect существует только с Android 9, ниже его нет физически.

## Архитектурные правила
- UI читает данные ТОЛЬКО из Room. Никогда напрямую из Health Connect или парсера архива.
- `ActivitySource` реализует источник, у которого можно спросить период (Health Connect,
  в будущем Strava). CSV-импорт и ручной ввод пишут в репозиторий напрямую.
- Доменный `ActivityType` — свой enum, не маппится один-в-один ни на Garmin, ни на `EXERCISE_TYPE_*`.
- Время активности хранится как локальное время старта.

## Как работаем
- Не берись за задачи из следующих блоков плана, пока текущий блок не закрыт по DoD.
- Перед реализацией — короткий план в чате, код после подтверждения.
- Не добавляй зависимости без явного согласования.

## Комментарии в коде
- Комментарии в коде пишем по-английски. Документация в `docs/` остаётся на русском.
- Комментируем абстракции: интерфейс, метод интерфейса, сущность. Коротко — что это такое
  или что метод делает, что принимает и что возвращает.
- Остальное комментируем, только если это нужно программисту прямо сейчас, чтобы понять
  код, который он читает впервые.
- Не объясняй в комментариях причины решений: почему выбран такой подход — это `docs/`.
- Не пиши в комментариях историю («раньше было так») и планы («в блоке N заменим»).
- Не повторяй в коде то, что уже написано в `docs/`.
- Комментарий, который пересказывает имя функции или поля, не нужен.

## GitHub
- Одна issue на блок плана, подпункты блока — чеклистом в теле задачи.
  Не дроби блок на отдельные issue.
- Issue привязывается к milestone M0–M3 из плана.
- Ветка на блок: `block-N-краткое-имя`. Спайки: `spike/имя`, в main не мержатся.
- Коммиты на английском, в повелительном наклонении: `Add ActivityDao range query`.
  Один коммит — одна законченная мысль, а не «всё, что накопилось».
- PR на блок, не на коммит. В описании: что сделано и почему так на английском `Closes #N`.
  Мержить squash. Мелкие правки — коммитом сразу в main, без PR.
- Не создавай issue, PR и релизы по своей инициативе — только по прямой просьбе.
- Не добавляй в сообщения коммитов пометки о генерации.
- Никогда не делай force-push и не переписывай уже отправленную историю.
  `--amend` — только для незапушенного коммита.
- Перед коммитом проверь, что не уходят: `local.properties`, `.idea/`,
  `*.jks`, `*.keystore`, папки сборки.
- Блок не закрыт, пока не обновлены документы в `docs/` из его DoD.
- В примерах данных внутри `docs/` не должно быть реальных идентификаторов
  аккаунта, почты и координат тренировок — заменяй на синтетические.
